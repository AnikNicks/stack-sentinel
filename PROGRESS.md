## Key decisions

- **Layers + events + incidents, never a trend line.** The first revision attempt just
  renamed financial KPIs with software-sounding names while keeping the same "one scalar
  drifting across cycles" mechanic — rejected. The real fix restructures the domain: a
  structured per-cycle snapshot (`layers` + `operational_health` + `behavior_incidents`)
  replaces the scalar KPI dict everywhere, and `change-impact-synthesizer`'s job changed from
  smoothing a numeric curve to causal event-attribution.
- **Destructive changes get a second gate beyond "route to a human."** Every other risk
  finding in this system routes to `human_review` and stops there. Destructive layer changes
  get their own module (`pulse/human_approval.py`) whose only function structurally cannot
  return `action_taken: True` — a stronger guarantee than "a human is in the loop," because
  there is no automated path to gate in the first place.
- **The company apps stay read-only, scripted-data-authoritative.** Confirmed explicitly with
  the user: clicking through a company app's product surface never feeds the monitoring
  pipeline. This keeps the Phase-3 simulation's exact incident count/routing reproducible
  regardless of what a viewer does in either web UI.
- **`FLAGGED_CLASSIFICATIONS` stayed `{drifted, warning, breach}`** (not widened to include
  `watch`) — matching the original project's design of counting only the worst per-track
  state. This meant the S06/S09 incident narratives needed a raw `drifted` read that's
  honestly defensible on its face (see Phase 3 above), not a softer `watch`.
